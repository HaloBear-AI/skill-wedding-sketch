# 成图验收清单

打开本轮使用的参考图或用户描述、通过检查的 brief、该文字模式的定位清单和成图。读取图像的像素宽高，核对目标画幅。缩看整板检查构图，再放大到能逐字阅读的大小。每次修复后按当前成图重查七项。

## 七项评分

每项满分 2 分，总分 14 分。合格要求总分至少 12 分，所有关键项各得 2 分，其余各至少得 1 分。关键项失败或出现 0 分项时，按对应排错步骤处理。

| 项目 | 2 分 | 1 分 | 0 分 | 修复 |
| --- | --- | --- | --- | --- |
| 1. 画幅与布局（关键） | 单张目标比例竖版。标题和主透视图完整，有设计说明区和 3–5 条主引线。中下左区是正、侧、俯和结构分解四图，右区是 3–4 个特写。底带有 1–5 项材质和 6–8 色。位置与选定版式相符。 | 模块和数量齐全，局部位置拥挤或分区明显偏移。 | 错画幅、横版、分成多张、任一模块缺失、裁切或数量出界。 | [版式挤乱或模块丢失](troubleshooting.md#版式挤乱或模块丢失) |
| 2. 手绘质感 | 纸面、手绘线条和着色层次贯穿全板。默认用米白水彩纸、针管笔、水彩和马克笔。输入 B 可按 brief 采用参考板的纸面和笔触。 | 整体手绘成立，局部材质过于光滑或笔触偏弱。 | 主效果图仍呈实拍或 3D 渲染质感。 | [画风偏照片或渲染](troubleshooting.md#画风偏照片或渲染) |
| 3. 设计一致性（关键） | 按下方输入类型和保真模式检查通过。主图和各视图的构件关系相符，支承与布艺挂点合理，特写对应主图中实际出现的对象。 | 核心设计尚可辨认，次要构件、花艺落点或特写出现可修复的可见偏差。 | 主结构、主花材、主色或空间关系违反模式约定，推断冒充图中事实，或主装置明显悬空失稳。 | [原设计跑偏或局部失真](troubleshooting.md#原设计跑偏或局部失真) |
| 4. 文字与留白（关键） | 所有可见文字与当前模式的清单逐字相符，清晰可读，位置和数量正确。无字底图按下方对应标准检查。 | 内容与清单相符且可读，局部字距、对齐或留白待修。 | 任一必需文字错漏、乱码、不可辨认、多出文字或违反模式约束。 | [文字乱码或挤压](troubleshooting.md#文字乱码或挤压) |
| 5. 三视图尺寸（关键） | 正、侧、俯的尺寸标注按同一组宽、高、进深检查通过，尺寸线对应实际轴向，单位和估算状态正确。无字底图按下方对应标准检查。 | 数字与单位符合要求，某一尺寸线位置或端点关系需调整。 | 数字矛盾、漏填、不可辨认、单位错误或漏标估算，或尺寸线归属无法确认。 | [三视图尺寸不一致](troubleshooting.md#三视图尺寸不一致) |
| 6. 材质与色板 | 色板反映骨架、花艺、布艺等实际着色。各材质示意能在主图找出对应构件。 | 主色和材质关系相符，一处非主色或纹理有轻微偏差。 | 色板主色与画面脱节，材质示意与关键构件冲突。 | [材质和色板偏离](troubleshooting.md#材质和色板偏离) |
| 7. 图面洁净（关键） | 品牌标识、水印、真实可识别人物和额外人物均为 0 处。 | 只出现局部脏边或可修复的无意义符号。 | 出现品牌标识、水印、真实可识别人物或额外人物。 | [多出标识或人物](troubleshooting.md#多出标识或人物) |

按安全区内高度检查分区，`classic` 约 55%／35%／10%，`detail` 约 50%／40%／10%。复核无字底图时，用形状、线条、留白和色块确认模块齐全。 [版式规范](board-layout-spec.md)

## 按模式复核设计

- `faithful` 核对结构形式与支撑、主花材的形态与位置、主色、空间布局四项。花种看不清时对照观察到的花型与分布。
- `reinterpret` 核对用户要求的新内容，并对照未指定改动的结构、落位与其他约束。
- 输入 B 核对参考手绘板中应延续的版式组织、笔触和上色方式。
- 输入 C 单独核对可见局部。所有用于补全的背架、挂点、估算尺度或花材信息都能在 `inferred_fields` 找到对应记录。用户描述与参考中所见分别标明来源。

## 按模式复核文字

| 模式 | 2 分的复核方法 |
| --- | --- |
| `full` | 从标题开始逐个比对位置与清单引号内原文。每个空间定位计一块，同一字块的主副词或多行说明合计一块。全图最多 28 块。中文引线主词最多 8 字，副词最多 6 字。设计说明正文最多 3 行且中文总计不超过 60 字，标点计入字数。每个特写正文最多 3 行。 |
| `minimal` | 逐字核对主标题、四个视图名、六个数字和正视图标题次行的单位或估算提示。其余模块保留图形和预留位置，文字数量为 0。 |
| `none` | 放大扫描标题、引线、视图、细节和底带，确认全板文字、字母、数字、伪字数量为 0。检查每块留白和交付的完整后期定位清单相符。 |

## 逐个读取尺寸

1. 从 `structure.dimensions` 抄录 `width_mm`、`height_mm`、`depth_mm` 和 `estimated`。核对 `views` 对应尺寸和当轮定位清单。结构分解图用于读构件关系，六个尺寸数字全部来自正、侧、俯视图。
2. 在 `full` 或 `minimal` 成图逐个读取尺寸线旁的数字。先确认尺寸线归属，再读出数字。门洞形状、线长和比例仅供构图检查，数字矛盾、缺字或无法辨认按失败处理。

   | 同一尺寸 | 出现位置 |
   | --- | --- |
   | 宽 W | 正视图宽 ＝ 俯视图宽 |
   | 高 H | 正视图高 ＝ 侧视图高 |
   | 进深 D | 侧视图进深 ＝ 俯视图进深 |

3. 将六个数字与 brief 逐一比对，确认均为毫米。技术区共用单位和估算状态，统一放在正视图标题次行。`estimated` 为 `true` 时，中文写“尺寸估算 · mm”，英文写“Estimated · mm”。为 `false` 时，写“单位 · mm”或“Units · mm”。
4. 验收 `none` 底图时，对照 brief 与完整定位清单核对上述三组数字和提示。再检查图中的六处尺寸线、端点和排字留白。报告底图尺寸线结果，并将实际数字与标签的可读性标为待复核。排字完成后，用 `full` 或 `minimal` 对应方法复核交付图。

## 脚本与无成图交付

- `validate_skill.py` 检查 Skill 的结构和引用。`validate_brief.py` 检查 JSON 字段、枚举、文案限制和尺寸数据关系。图中真实画了什么、采用哪种质感、文字是否清楚，均用上表检查。
- L2／L3 逐项核对 brief、提示词包、参考图角色、文字清单、尺寸和适用参数。按实际提供的参考资料报告可完成的检查。将成图七项标为待验，成图总分留空。
- 交付时记录文字模式、当前成图或底图状态、已评分项与总分、失败或待验项，以及实际追加生成次数。标明仍需后期排字的范围，或说明有问题的视图和数字。
