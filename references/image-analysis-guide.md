# 参考图解析

先确定输入分支，再按图中可辨认的内容填写 [design brief](design-brief-schema.md)。用 `{zh, en}` 记录中英双语自由词条，保留同一位置、颜色和材质含义。

## 判定输入分支

| 类型 | 判断条件 | 处理 |
| --- | --- | --- |
| A | 实景照或 3D 效果图能看清主体轮廓、主要构件和落位关系 | 把设计转成手绘方案板。保留开口、花材及疏密、主色、焦点和动线。单视角看不到的背面、尺寸与连接做示意并标推断。 |
| B | 已有手绘方案板，可以辨认原板的分区、笔触和主体设计 | 先读原板的标题、主图、三视图、细节和底栏的位置。记录纸色、线宽、笔触、色彩质地与留白，组装时沿用可辨认的版式和画风。 |
| C | 草图、局部特写，或缺少辨认主体和落位关系所需的信息 | 保留已知部分，选与已知构件、用途和空间相容的一套补全，逐项记录补入的内容和理由。 |

以能看见的内容判定。只有花艺的照片走 C，能看清整体的单张透视照片可走 A。仅当 A、B、C 的选择会改变交付且仍无法判定时，问一个分支问题，例如“参考图是完整场景照片或效果图、已有的手绘方案板，还是一张草图或局部特写？”

默认使用 `faithful`，保留已知的结构、花材、配色和位置关系。使用 `reinterpret` 时，记录用户授权的变动范围，依照该范围改设计并延续参考画风。花色调整时查对色板、主图、细节和图例。结构调整时同步重做相关视图与尺寸。

L3 时索取文字描述或填写好的 brief，按描述判定分支，明确内容来自用户描述。把叙述中的已知项照录，将其余补全项列入 `inferred_fields`。交付提示词包时，请用户在支持参考图的生图环境附上原图。

## 顺序读图

| 读取内容 | 记录方式 |
| --- | --- |
| 场地、功能区与方向 | 先确认户外草坪、宴会厅、海边、林地或教堂等场景，再判定仪式区、舞台、迎宾区、合影区、甜品台或通道。以宾客面对装置的方向为正面，记录主效果图的正面或斜侧视角、台前台后、左右及开口方向。写入 `scene`。 |
| 主轮廓与骨架 | 先读整体形体和开口，再查立柱、横梁、面板、底座或可见的吊挂支承。看表面时写可辨特征，例如“浅木纹饰面”，隐藏的芯材与连接件只按示意补全。写入 `structure`。 |
| 花艺 | 依次辨认主花、配花、叶材、花团形态、疏密渐变和落位。用画面位置描述，例如“左上密集、向中梁渐疏，右脚为低位花团”。物种分不清时写“奶白重瓣花”或“浅绿球形花序”。写入 `florals.main`、`accent`、`foliage`、`form`、`placement`、`colors`。 |
| 布艺 | 读出透光性、厚薄、褶向、从哪里起挂、在哪里收束、下摆离地或拖地。用 `fabrics` 按组记录 `type`、`color`、`drape`、`fixing_points`。只看见垂坠时，把未露出的挂接位置标推断。 |
| 焦点与道具 | 确定纸艺花、字牌等焦点的尺寸感、朝向及安装位置，用 `focal_elements` 记录。独立座椅、路引和台面用 `furniture_props` 记录，标清它们与主体、入口或通道的关系。 |
| 色彩、光线与气氛 | 优先读花、布、主体和叶材的中间色，区分现场色光与材质固有色。记录光的方向、软硬和可辨的时间线索，并用 6–8 个对应主体的色块写入 `palette`。近似取色得到的 HEX 要记录估算依据。 |
| 注解与特写 | 选择最能解释设计的 3–5 个可指认构件写入 `callouts`，把其落点写清。挑选 3–4 个能看清楚纹理、层次或落位的局部写入 `detail_zooms`。用画面中实际出现的材质写 `materials_legend`。 |

若纸艺与真花的区别、材质或时间无法确认，优先写已见的外观和光线。例如仅有侧光线索时，记录“柔和侧光”。遮挡会影响侧视或俯视时，把决定视图的未知部分写进推断说明。

## 校对尺寸与推断

1. 优先采用用户提供或原板清楚标注、单位与边界一致的三向尺寸。按同一主体的安装外包络量宽、高、进深，包含底座与随主体安装的布艺、花艺和装饰。将独立座椅、路引和其他游离道具留在外包络之外。
2. 只有比例线索时，用与主体近似同深度的可靠物件做参照，按相对比例粗估。单张透视照片的深度缩短与近大远小会影响比例。缺少可靠比例时，按 [婚礼行业参考](wedding-domain-knowledge.md) 取与现场相容的区间，选圆整的毫米数。
3. 将结果统一写入 `structure.dimensions.width_mm`、`height_mm`、`depth_mm`。任一轴靠推算或设计暂定时，把 `estimated` 设为 `true`，记录相关字段并在成品标为估算。
4. 从同一组三值生成 `views`。正视图取宽、高，侧视图取进深、高，俯视图取宽、进深。分解图沿用相同构件及接触位置示意。
5. 给每个补全值写最具体的 JSON Pointer 及双语理由。使用从 0 开始的数组下标，路径对应 brief 中实际存在的字段。通过字段位置定位推断，使后续修订可以逐项替换。

```json
{
  "inferred_fields": [
    {
      "path": "/structure/dimensions/depth_mm",
      "reason": {
        "zh": "花团遮住底座，按可见的落地轮廓暂估。",
        "en": "The floral cluster obscures the base, so depth is estimated from the visible ground outline."
      }
    },
    {
      "path": "/fabrics/0/fixing_points",
      "reason": {
        "zh": "布顶被花遮挡，沿上缘暂示意挂在横梁。",
        "en": "Flowers obscure the fabric top, so a crossbeam attachment is shown schematically."
      }
    }
  ]
}
```
